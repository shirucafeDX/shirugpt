# 保存会話による入力形式の比較（2026-10-25）

この比較はInteractions API移行前の`generate_content`方式を対象とする。
以下の「現在形式」「新形式案」はCSV返却と既読応答の要点化の比較であり、
その後に実装したAPI側の状態保持・差分送信の効果を測定した数値ではない。

## 結果

本日（日本時間）更新されたGemini 3.8 Flashの保存会話6件を読み取り、保存されたモデル応答の直前114地点を再構成した。
3方式すべてが現在の履歴予算内に収まる112地点を、同じ地点の組で集計した。
数値は送信JSONのUTF-8バイト数÷3による**推定値**であり、API実測トークン・請求額ではない。

| 方式 | 累計推定入力 | 旧形式比 | 現在形式比 |
| --- | ---: | ---: | ---: |
| 旧形式相当：行ごとのJSON・統計・サンプル | 1,494,576 | — | — |
| 現在形式：CSV／列情報・現在の予算制御 | 1,471,226 | −1.56% | — |
| 新形式案：既読のCSV応答を既存要点＋結果IDへ置換 | 1,451,751 | −2.87% | −1.32% |

この保存会話群では、CSV応答の追加要点化だけで数十%の全体削減にはならなかった。
新形式の追加削減は19,475推定トークン。小さいCSVでは置換後の方が大きければ原文を維持した。

## 方式の定義

### 旧形式相当

保存済みの旧形式`sample_rows`を含む応答はそのまま利用。
現在形式のSQL結果は、保存済みDataFrameに`summarize_dataframe`
（最大500サンプル行）を適用して、行ごとのJSON形式へ戻した。
SQL以外のCSV応答は受信済み範囲の行をJSON・統計へ変換した。
旧バージョンのアプリ全体の完全再現ではなく、データ返却方式の比較である。

### 現在形式

2026-10-25の比較実行時の作業ツリーにある送信処理を使用。
既存のCSV／列情報応答はそのまま利用。
旧形式のSQL応答は保存済みDataFrameから現在の`TokenBudgetManager.initial_result`で再構成。
初回直接返却100行、分析・参照50行、データ上限8,000、縮小目標4,000、履歴上限16,000の設定。
元表を復元できずサンプルだけの場合は、保存サンプルの範囲であることを付記した。

### 新形式案

現在形式と同じ履歴・同じAPI呼び出し順を維持する。
初めてモデルへ渡るCSVは変更しない。
後続の生成で再送されるCSV応答のうち、その時点で有効な`context_note`が実際に残っているものを、
既存の要点・`result_id`・結果目録・取得範囲・切り捨て・警告・ページング情報へ置き換える。
CSVの文字列だけでなく、不要になる形式説明や応答の付帯情報も縮小する。
参照先の原データは保存済みDataFrameを維持する想定。

要点がない結果に新しい事実要約を捏造しない。要約生成APIは呼ばない。
履歴予算による省略後の現在形式を土台にすることで、新形式だけが古い履歴を多く保持して比較量が変わることを防いだ。
署名付きmodel Part、SQL、ツール呼び出し引数は変更しない。

## ツール定義の扱い

**全方式とも、すべてのツール定義を一括送信する条件にはしていない。**

- `select_tools`を含む現在形式の会話1件は、選択履歴を逐次復元し、選択された定義だけを各地点で計上。
- 旧形式の5件には選択履歴がないため、その地点で実行されたツールの定義だけを渡す共通条件を仮定。
  当時の全ツール一括送信は再現せず、追加の選択用生成も仮想追加していない。
- システム指示・選択ツール定義の推定量は、同じ比較地点では3方式で一致させた。

したがって全6件の集計は制御条件下の参考試算。
現在の選択方式を保存履歴からそのまま復元できる会話の結果は次のとおり。

| 方式 | 1会話・29地点の累計推定入力 |
| --- | ---: |
| 旧形式相当 | 494,414 |
| 現在形式 | 504,115 |
| 新形式案 | 494,699 |

この会話では新形式が現在形式より**9,416（1.87%）削減**した。
旧形式と新形式はほぼ同じ大きさ。小さい結果ではCSVの列・型・null表現・形式説明の付帯情報が、
行JSONによる列名の繰り返し削減を上回る場合がある。
なお、先行試算の0.38%はCSVフィールドだけを除去し、その他の応答情報を残した場合。
上記1.87%は、既読応答全体を要点・参照情報に置き換えた場合である。

## 現在形式の入力内訳

112地点の累計。各要素を別々に推定するため、丸め誤差を含む。

| 要素 | 推定入力 | 全体比 |
| --- | ---: | ---: |
| システム指示 | 440,881 | 30.0% |
| 選択済みツール定義 | 163,173 | 11.1% |
| CSV本文 | 53,226 | 3.6% |
| その他の履歴・応答情報 | 813,946 | 55.3% |

必要時取得のツール定義を前提としても、CSV本文が全体に占める割合は小さい。
この履歴群では、CSV以外の履歴・指示を各生成で繰り返し送ること、生成回数そのものが重要になる。

## 要点がない応答も削除した場合の参考値

要点がない既読CSVも、行数・列・結果IDなどのメタデータだけに置き換える参考計算では、
累計1,398,035（現在形式比−4.97%）となった。
これは数値の結論を引き継がないため、同等の回答品質を保証する方式ではない。
後から詳細参照が増える可能性もあるので、実用時の削減率として採用しない。

## 検証と限界

- 原本は読み取りのみ。BigQuery再実行・Gemini生成は行っていない。
- 状態は会話先頭から再生し、後から作られた要点を以前の生成へ混ぜていない。
- 新形式でモデルが初めて読むCSVが変わらないことを検査。
- 新形式で署名付きmodel Part・function callが変わらないことを検査。
- 現在形式と新形式で保持する履歴を揃え、新形式の推定入力が増えないことを検査。
- 3方式でシステム指示・選択ツール定義量が一致することを検査。
- 保存元SDKの追加された空フィールドはローカル復元時に除外。非空データと署名は保持。
- 保存済み応答の直前を比較しており、応答の残らない失敗呼び出し・再試行は再現しない。
- 回答経路を固定した比較。新形式に変えたときのモデルの判断・参照回数・正確さは未評価。
- JSONのバイト数に基づく推定は、署名のモデル内部での数え方やキャッシュ割引を再現しない。
  この数値を実入力トークン・料金として解釈しない。

比較プログラムと地点別の集計は、ローカル一時領域
`/tmp/shirugpt-token-comparison/`に保存。`formats.py`が3方式を再構成し、
`compare.py`が時系列再生と要点置換を行う。元会話を含む一時ファイルはリポジトリへ追加していない。
