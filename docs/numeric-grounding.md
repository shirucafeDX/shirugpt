# 数値の受け渡し・回答確定・根拠照合

## 実装の範囲

1. SDKが送るツール結果を、送信前の結果とSHA-256で照合する。
2. 数値だけを求める質問では、最終回答用のSQLが1行1数値列を返した場合に、そのセルから回答を確定する。
3. 分析回答では、モデルが指定したセルや計算からアプリが数値を埋め込み、引用元を保存・表示する。

数値と参照先・計算結果を対応付ける仕組み。SQLの業務定義や、文章中の因果関係・解釈まで完全に証明するものではない。

## 受け渡し形式

ツール結果全体をJSON文字列として送る旧方式では、固定したCSVの数値と結果IDを転記させる実API試験で、両方が不一致になる条件を確認した。同じ内容をオブジェクトで渡した条件では一致した。送信リクエストにも元の値が存在したため、単なる元データの取り違えではない。この比較は単発試験であり、プロバイダー内部で何が起きたかを断定するものではない。

新方式は結果をオブジェクトで送る。ただし、Vertex Interactionsで空配列をそのまま送ると型のエラーが再現し、SDKがオブジェクト内のnullを省略するケースも確認した。このため、送信時だけ以下の表現にする。

| 元の値 | 送信時の表現 |
| --- | --- |
| 空配列 | `{"__shirugpt_value__":"empty_list"}` |
| 空オブジェクト | `{"__shirugpt_value__":"empty_object"}` |
| null | `{"__shirugpt_value__":"null"}` |

元の保存会話・DataFrameは変更しない。ゼロ・false・空文字は保持する。空配列が「現在の未解決事項なし」を意味することもモデルへ明示する。旧形式を使ったAPI状態は一度だけ要点から作り直し、不確かな過去の受け渡しをそのまま継続しない。

アプリで生成するクライアントにはHTTP送信フックを設定する。送信前と実送信のツール結果を意味上同じJSONへ正規化して照合し、不一致なら送信を止める。保存するのはツール名・結果参照・送信形式・結果とCSVのハッシュ等であり、認証ヘッダーや本文そのものは追加保存しない。独自クライアントを渡し送信フックを設定しない呼び出しでは、送信予定ハッシュのみとなり、実送信の照合済みとは表示しない。

## 単一数値の直接回答

「数値だけ」「数字のみ」などの明示的な依頼が対象。成功したrun_queryの最終回答用結果が、非切り捨て・1行1列・有限の数値である場合に確定する。途中結果（supporting）、複数候補、複数行・列、欠損値などでは勝手に選択しない。

確定時には、元の結果ID・列名・0始まりの行番号・値・回答のハッシュを保存する。取得値を改めてAIに再入力させないため、単一数値を言い換える最終AI呼び出しも省ける。SQLが質問に合うかの判断と安全性検査は従来の処理を使う。直接回答後のAPI状態も維持し、次の質問では保存結果を参照できる。

## 分析文の数値

成功した結果にはR1、R2等の短いresult_refを付ける。実際の結果IDとの対応はアプリが管理し、要約のreferencesや参照ツールの入力も変換する。未知のIDを推測で補正しない。

モデルはfinish_answerのanswerに`{{key}}`を書き、numeric_claimsで参照と計算を指定する。以下は構文例であり、実データの値ではない。

```json
{
  "answer": "参加数は{{attendees}}件、参加率は{{rate}}%です。",
  "numeric_claims": [
    {
      "key": "attendees",
      "operation": "cell",
      "sources": [{"result_ref": "R1", "column": "参加数", "aggregate": "sum"}]
    },
    {
      "key": "rate",
      "operation": "ratio",
      "sources": [
        {"result_ref": "R1", "column": "参加数", "aggregate": "sum"},
        {"result_ref": "R1", "column": "予約数", "aggregate": "sum"}
      ],
      "as_percent": true,
      "decimals": 1
    }
  ]
}
```

参照方法は次のいずれか1つ。

- row_index: 保存済み原表の0始まりの行番号。
- aggregate: 指定列全体のsumまたは非NULL件数count。切り捨てられた表の全体集計は拒否する。
- row_filters: 列・文字列値で原表の行を特定する条件。必ず1行に一致させ、曖昧な場合に先頭行を選ばない。フィルターやページング後の表示行番号を原表の番号と誤認しないためにも使える。

計算はcell、sum、difference（後−前）、ratio（前÷後）、percent_change（後−前を前で割り百分率）のみ。任意の式やevalは実行しない。Decimalを使い、指定した小数桁へ四捨五入する。比率・増減率の既定は2桁、指定可能範囲は0〜6桁。文字や日時のラベルも元セルから挿入できるが、数値書式では変換しない。

直書きの分析数値、未定義・未使用・重複したkey、不正な行・列、存在しない結果、ゼロ除算、欠損値、無限大などは拒否する。アラビア数字だけでなく「五万件」のような表現も検査する。箇条書きの段階番号は除外する。提案上の期間など元データに根拠のない設定は、データ分析文では「短期間」など数値以外で述べる。

回答の元になるセル・式と値を確認した後に、検証済みの回答から要点メモ・会話要約を作る。AIが別途書いた未検証の数値を、そのまま確定事実の要約に残さない。

## 実行詳細と記録

- 「数値の根拠」: 検証状態、値、元の結果ID・列・行、計算式、丸め桁数。
- 「ツール結果の送信記録」: ツール結果と送信JSONの照合結果、送信形式、結果・CSVのハッシュ。
- 保存会話: 上記の対応表、受信イベント、原本DataFrameを保持する。
- BigQuery: 既存の使用量・エラーログを使う。数値の対応表・送信ハッシュの専用列は追加していない。

## 手動の接続診断

合成データだけを使い、短い指示／アプリ相当の指示と、旧JSON文字列／新オブジェクト形式の4条件を比較する。実APIを最大8回呼び、SQLは実行しない。

```bash
PYTHONPATH=. .venv/bin/python scripts/diagnose_numeric_handoff.py --output /tmp/shirugpt-handoff-results.json
```

生の認証情報を出力しない。新規の独立した会話で試し、数値・IDの一致、送信照合、所要時間、報告された使用量を結果ファイルで確認する。送信形式の不具合を再現するため、旧形式はこの診断プロセス内だけで使用する。

## 制約

- 検証できるのは保存結果との数値の対応と明示した計算。文章の意味、因果推論、適切な分母・対象期間の選択などは別途確認が必要。
- 数値の参照指定を修正するAI呼び出しが増える場合がある。正確性に加え、修正回数・入力トークン・遅延を継続して比較する。
- この処理はAIが作る任意の算術回答を全てコードで置き換える汎用計算器ではない。
