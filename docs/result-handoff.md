# 回答とツール結果の受け渡し

回答の数値検証は撤廃した。モデルが回答文を生成し、アプリは数値・年月・学年・段階番号を理由に拒否しない。numeric_claimsや{{key}}の指定、計算式からの値の差し込み、単一セルからの自動回答は行わない。通常の文章回答も数値を理由に非表示にしない。

要点メモの形式と参照IDは履歴管理のために検査する。回答の数値を元データと照合する処理ではない。

## 保存結果の参照

保存表にはR1、R2等の短いresult_refを付け、実際の結果IDとの対応を保存する。以前の会話の参照名も再利用できる。元のSQL、取得済みDataFrame、要点メモは引き続き保存する。

## ツール結果の送信形式

結果はオブジェクトで送信する。Vertex Interactionsでの空値の型エラーやSDKによるnull省略を避けるため、送信時だけ空配列・空オブジェクト・nullを次の表現へ変換する。元の保存表や保存会話は変更しない。

| 元の値 | 送信表現 |
| --- | --- |
| 空配列 | `{"__shirugpt_value__":"empty_list"}` |
| 空オブジェクト | `{"__shirugpt_value__":"empty_object"}` |
| null | `{"__shirugpt_value__":"null"}` |

アプリが作成したクライアントでは、HTTP送信フックで元のツール結果と実送信JSONのハッシュを照合する。不一致の場合は送信を止める。記録するのはツール名、参照ID、送信形式、結果とCSVのハッシュ等。認証ヘッダーや本文を追加保存しない。独自クライアントでフックを設定していない場合には実送信照合済みと表示しない。

この照合は通信内容の同一性の確認であり、モデルの回答やSQLの業務上の正しさを検証するものではない。

## 保存済み会話からの継続

以前の数値検証用ツール呼び出し・エラーをAPI状態から引き継がないよう、回答方針バージョンが異なる場合は要点・保存結果を使って状態を一度再構成する。過去の会話原本は書き換えない。再構成後は通常の状態IDによる継続を行う。

## 手動の接続診断

合成CSVの転記について、短い指示/アプリ相当の指示と旧JSON文字列/オブジェクトの4条件を比較できる。最大8回の実API呼び出しを行い、SQLは実行しない。

```bash
PYTHONPATH=. .venv/bin/python scripts/diagnose_numeric_handoff.py --output /tmp/shirugpt-handoff-results.json
```

これは接続診断であり、通常の回答に数値検証を適用するものではない。
